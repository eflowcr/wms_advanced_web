Qué resuelve, y cuándo NO usarlo

Qué resuelve

Las reglas en un solo lugar, sobre Signal Forms: se valida al salir del campo y al enviar, nunca mientras se escribe; al enviar con errores aparece el resumen y se enfoca; Ctrl+S envía desde cualquier campo.

Guardar nunca se deshabilita: un botón apagado no dice qué falta.

Cuándo NO usarlo

  • Si es un solo campo que aplica al tocarlo (un toggle de preferencia), no hay formulario: no hay nada que enviar.
  • Si el formulario es una búsqueda, va el patrón Filtros: aplica al cambiar y no se envía.

Demo principal — alta de una expedición

Pulsá «Guardar» sin llenar nada: aparece el resumen, cada campo dice qué le falta y el foco cae en el resumen. Con todo bien, «Guardar» queda en carga hasta que el acción del envío termina.

Variantes — cómo se compone

  • Una columna. Dos columnas solo para campos cortos emparentados (almacén, fecha, estado, bultos), y solo cuando la pantalla es ancha.
  • Secciones con fieldset y legend: un lector de pantalla anuncia en qué grupo está cada campo.
  • Pie con Cancelar y la primaria a la derecha. Si el formulario es más alto que la ventana, el pie se fija abajo (sticky), para no buscar «Guardar» con la rueda.
  • Asterisco en la etiqueta de cada obligatorio —lo pone el campo leyendo el validador, no se escribe a mano— y la leyenda «* obligatorio» una vez por formulario.

Matriz de estados

@switch (column.id) { @case ('moment') { @switch (row) { @case ('typing') { Mientras se escribe } @case ('leaving') { Al salir del campo } @case ('invalid') { Al enviar con errores } @default { Al enviar válido } } } @case ('field') { @switch (row) { @case ('typing') { su hint, sin error } @case ('leaving') { el mensaje del validador que falló, en lugar del hint } @case ('invalid') { todos los mensajes, aunque no se haya visitado el campo } @default { sin mensajes } } } @default { @switch (row) { @case ('typing') { Guardar habilitado } @case ('leaving') { sin resumen todavía } @case ('invalid') { resumen arriba, enfocado, con un enlace por campo } @default { Guardar en carga mientras la acción del envío corre } } } }

Tamaños

No aplica — Medium

Los campos van en su tamaño por defecto: un formulario es la tarea de la pantalla, no un control de una barra.

Anatomía y tokens

  • Sin token propio. El resumen es un <ewms-banner> de peligro, y los mensajes usan --color-danger-text por la clase del campo.
  • Dónde vive: lib/forms/ — la directiva, el token de mensajes, confirmDiscard y field-note.ts, que es de donde cada campo saca el texto del validador que falló.

Accesibilidad

  • Cada mensaje se une a su campo por aria-describedby, y el campo queda aria-invalid.
  • El resumen es un role="alert" (Banner de peligro) y recibe el foco: quien usa lector de pantalla se entera sin buscar.
  • Cada enlace del resumen lleva al campo y lo enfoca; el asterisco es aria-hidden porque required ya lo anuncia.
